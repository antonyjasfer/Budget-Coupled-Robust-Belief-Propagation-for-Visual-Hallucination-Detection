# Final Data Provenance, Acquisition, and Scientific Lock Policy

**Milestone:** Phase 9E  
**Schema Version:** 1.0.0  
**Effective Date:** September 2026  
**Scope:** MS COCO 600-Image Representative Cohort, Evidence Provenance, Double Human Annotation, and Scientific Lock Protocol.

---

## 1. Executive Summary & Purpose

This document codifies the mandatory provenance, sampling, annotation, and cryptographic locking rules for the 600-image MS COCO visual hallucination benchmark. 

The core mission of Phase 9E is ensuring that dataset curation, pre-label stratification, and split freezing are scientifically isolated from downstream inference, robust interval width, model accuracy, and human ground-truth labels. Under no circumstances may dataset composition, sampling rules, or partition assignments be altered post-hoc in response to model performance, disagreement rates, or event frequencies.

---

## 2. Seven-Level Data Provenance Taxonomy

Every data record, image reference, claim, and evidence bundle in the benchmark must bear an immutable provenance state from the following seven-level canonical taxonomy:

| Provenance State | Description | Permitted in DEVELOPMENT Mode | Permitted in FINAL Locked Mode |
|---|---|:---:|:---:|
| `REAL_UNLABELED` | Real MS COCO images and extracted claims before human annotation. | Yes | No (must be resolved) |
| `REAL_HUMAN_ANNOTATED` | Claims annotated by an independent human annotator (Annotator A or B) under masked protocol. | Yes | Yes (prior to adjudication) |
| `REAL_ADJUDICATED` | Claims where any A/B disagreement or ambiguous state has been resolved by an independent adjudicator. | Yes | Yes (canonical final benchmark) |
| `SYNTHETIC_FIXTURE` | Programmatically generated synthetic images, claims, or mock tensors used for unit tests. | Yes | **STRICTLY FORBIDDEN** |
| `MOCK_ANNOTATION` | Synthetic or simulated ground-truth annotations generated by test scripts or heuristic mocks. | Yes | **STRICTLY FORBIDDEN** |
| `PSEUDO_LABEL` | Labels derived from heuristic model predictions, detector thresholds, or external self-training. | Yes | **STRICTLY FORBIDDEN** |
| `DEVELOPMENT_ONLY` | Experimental, exploratory, or pilot data explicitly quarantined from the final benchmark. | Yes | **STRICTLY FORBIDDEN** |

### Hard Isolation Enforcement
In `FINAL` mode, the validator (`scripts/validate_final_dataset.py --mode FINAL`) executes an adversarial verification check. Any record bearing `SYNTHETIC_FIXTURE`, `MOCK_ANNOTATION`, `PSEUDO_LABEL`, `DEVELOPMENT_ONLY`, or unadjudicated/unlabeled claims immediately halts execution with an exit code of 1 and invalidates the candidate dataset lock.

## 3. Representative Primary Cohort vs. Subgroups

### 3.1 Representative Primary Cohort Definition
The primary representative cohort consists of exactly 600 images sampled from the eligible MS COCO candidate population.
- **Pre-label sampling rule:** The sampling rule must depend strictly on immutable image-level metadata (e.g., COCO image ID, valid file presence, standard license, minimum resolution).
- **Prohibited selection criteria:** The primary cohort selection rule **MUST NOT** depend on:
  1. Generated claim counts ($G \ge 2$),
  2. PGM graph size or connectivity,
  3. Model evidence scores (OWL-ViT, CLIP, LLaVA confidence),
  4. Human ground-truth labels or disagreement rates,
  5. Robust inference outputs, interval widths, or model correctness.
- **No Replacement:** Images generating only 1 claim must **NOT** be discarded or replaced to artificially inflate graph complexity.

### 3.2 Graph-Evaluable Subgroup ($G \ge 2$)
After claims are extracted within the frozen primary cohort:
- Claims are stratified into:
  - $G_1$: 1 claim (isolated unary node; non-graph-evaluable for pairwise coupling),
  - $G_2$: 2 claims,
  - $G_3$: 3 claims,
  - $G_4$: 4+ claims.
- The subset of images with $G \ge 2$ forms the **Graph-Evaluable Subgroup**.
- **Crucial Rule:** Evaluating the $G \ge 2$ subgroup is a planned subgroup analysis. It must **NEVER** alter primary cohort membership or split assignments.

### 3.3 Graph-Stress Supplement (Optional)
If the primary cohort proves graph-poor, an additional graph-enriched cohort may be acquired using pre-label claim counts.
- It must be explicitly designated as the **GRAPH-STRESS SUPPLEMENT**.
- It must have its own distinct manifest (`graph_stress_manifest.json`), its own sampling rule, and separate metrics.
- It must **NEVER** be merged with the representative primary cohort, nor described as representative of natural MS COCO distribution.

## 4. Frozen Split Preservation & Image-Identity Integrity

The 600-image primary cohort is partitioned into frozen splits before human annotation:
- **Train:** 300 images (50.0%)
- **Validation:** 90 images (15.0%)
- **Calibration:** 90 images (15.0%)
- **Test:** 120 images (20.0%)

### Split Constraints:
1. **Inheritance:** All claims generated from an image strictly inherit that image's split partition.
2. **Identity Groups:** All image duplicate groups, transformations, and corruptions share the same `ImageIdentityGroup` and must reside in the exact same partition.
3. **No Post-Hoc Rebalancing:** Splits must never be re-partitioned after viewing human labels, hallucination rates, UNKNOWN counts, or model performance.
4. **Persisted Metadata:** The sampling manifest records `split_seed`, `split_algorithm`, image IDs, identity groups, and manifest SHA-256 hash.

---

## 5. Strict Prohibition on Absence Inference from COCO Annotations

MS COCO ground-truth object annotations are positive instance segmentations. The absence of an object annotation in COCO **DOES NOT** imply that the object is absent from the visual scene (due to unannotated background objects, label hierarchy differences, or partial occlusions).

**Mandatory Rule:**
- External COCO object annotations may be used for candidate filtering and category reference only.
- **NEVER** automatically derive `HALLUCINATED` from the absence of a COCO bounding box or segmentation.
- Ground truth visual support (`SUPPORTED`, `HALLUCINATED`, `UNKNOWN`) is established **exclusively** by independent human annotation under masked protocol.

## 6. Pre-Declared Evidence Failure Policy

During multi-modal evidence extraction (LLaVA, OWL-ViT, CLIP), every extraction attempt is categorized into one of four states:

1. **`AVAILABLE`**: Evidence successfully extracted and validated against schema.
2. **`UNAVAILABLE`**: Evidence missing or unretrievable. Defined policy:
   - The claim remains in the human annotation set.
   - The claim is excluded from specific model comparisons requiring that missing provider.
   - Causes `FINAL` validation failure if a required core evidence provider is missing for the final benchmark.
   - **Missing evidence MUST NEVER be substituted with numeric zero, default median, or fabricated scores.**
3. **`FAILED`**: Extraction encountered an unrecoverable runtime exception. Must record:
   - `reason_code`
   - `provider`
   - `attempt_count`
   - `last_error_class`
   - `provenance_status`
4. **`INVALID_PROVENANCE`**: Evidence claims real provenance but fails cryptographic hash check or model revision match. Immediately rejected.

---

## 7. Claim-Generation Versioning

Claim extraction logic is an integral part of the dataset specification:
- The extraction code commit SHA, spaCy/NLP parser versions, canonicalization dictionary version, and claim filter rules must be frozen.
- If claim extraction rules are updated, the resulting claims constitute a **NEW dataset schema version**.
- Claims must **NEVER** be regenerated after human annotation has commenced.

---

## 8. Human Annotation Protocol & Privacy

1. **Independent Double Annotation:**
   - Real human annotators (pseudonymously identified as `ANNOTATOR_A`, `ANNOTATOR_B`) independently annotate masked tasks.
   - Python code does **NOT** generate human labels; it exports masked task JSON files and imports completed human responses.
   - Task masking strictly hides: detector scores, CLIP scores, model confidences, Ising parameters ($\theta, \epsilon, J$), predictions, splits, and full generated captions.
2. **Adjudication:**
   - Any claim where Annotator A and Annotator B disagree, or where either marks `UNKNOWN`, enters the adjudication queue.
   - An independent adjudicator (`ADJUDICATOR_1`) resolves disagreements.
3. **Privacy:**
   - Personally identifiable annotator information (PII) is strictly prohibited. Only pseudonymous or opaque IDs are stored.

## 9. Three-Manifest Scientific Lock Architecture

The final dataset lock (`dataset_lock.json`) decouples data provenance from downstream experiment results. It references and cryptographically hashes three distinct, immutable manifests:

```json
{
  "schema_version": "1.0.0",
  "lock_timestamp": "2026-09-22T21:00:00Z",
  "code_sha": "b5955a976295933bdf62284eba3a6b480ea1ee6a",
  "sampling_manifest_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "evidence_manifest_hash": "ca978112ca1bbdcafac231b39a23dc4da786eff8147c4e72b9807785afee48bb",
  "annotation_manifest_hash": "4e07408562bedb8b60ce05c1decfe3ad16b72230967de01f640b7e4729b49fce",
  "sampling_manifest_path": "data/manifests/sampling_manifest.json",
  "evidence_manifest_path": "data/manifests/evidence_manifest.json",
  "annotation_manifest_path": "data/manifests/annotation_manifest.json",
  "cohort_counts": {
    "total_images": 600,
    "train_images": 300,
    "validation_images": 90,
    "calibration_images": 90,
    "test_images": 120
  }
}
```

### Two-Step Lock Creation Protocol
To prevent errors in lock generation:
1. **Pre-lock validation:** Validate all candidate artifacts against schema and isolation rules.
2. **Lock creation:** Generate the immutable lock manifest and write to disk.
3. **Independent verification:** Re-read all artifact files from disk, recompute SHA-256 hashes independently, and confirm match with `dataset_lock.json`.

### Exclusion of Performance Metrics
The dataset lock describes **DATA PROVENANCE ONLY**. It strictly forbids containing:
- Test F1, ROC-AUC, AURC,
- Model accuracy,
- Robust interval width,
- Standard BP or Robust BP outputs.
Experiment results belong strictly to experiment logs, preventing dataset identity from depending on downstream outcomes.

## 10. Sample-Size Precision Planning vs. Power Claims

Sample-size analysis for the 600-image cohort (120 test images) provides **precision planning**:
- Margin of error for binomial proportion estimation: $\mathrm{MoE} = z_{1-\alpha/2} \sqrt{\frac{p(1-p)}{n}}$.
- For nominal hallucination rate $p \approx 0.20$ and $n \ge 200$ test claims, 95% CI half-width is $\le \pm 0.055$.
- Post-hoc test event adequacy: Reports observed hallucination counts, errors, and disagreements descriptively. If test event counts are low, reports `LOW EVENT COUNT / NOT EVALUABLE` without altering models or thresholds.
- Statistical power claims (e.g. "80% power") are strictly avoided unless a specific effect size, variance model, and alternative hypothesis are mathematically specified.
